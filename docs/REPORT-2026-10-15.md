# Collab — full product review, 15 October 2026

What this is: a check of the whole product against the vision and the technical PRD, the test evidence behind each
claim, a screen-by-screen UI review (web and installed app), how Collab compares with what exists in the market, and
what is still missing before the 18 October submission. Everything stated as "verified" was run today against the
live deployment (build `2cdac26`, https://collab-55.web.app) or the test suite (104/104).

## 1. Verdict

Collab is a working product, not a demo: two people's agents find each other, negotiate inside private limits over
A2A, agree, pay (test mode), hand over with a one-time pickup pass, and leave a record anyone can verify with a
published key. Stock and time slots are reserved atomically, decisions have deadlines, goals can span several
providers with a shared budget, and outside systems (a POS, a calendar) connect with scoped, revocable grants.

Three things keep it from "finished": organisations with staff roles are not modelled (one person = one agent),
payments are simulated by design, and the interface has not been tested with real shopkeepers. Two regressions were
found and fixed during this review (§5, §8); both would have embarrassed us in front of judges.

## 3. Test evidence

- **Unit + end-to-end:** 104/104 (`cd server && npm run check`, strict TypeScript). End-to-end tests spawn the real
  server with the offline stand-in model and drive two accounts over real A2A HTTP.
- **Benchmark on real Gemini** (`docs/bench/full-armor-autorater`, Model Armor on): privacy attacks 100/100 blocked;
  legitimate questions 29/30 answered; negotiation 40/40 feasible pairs agreed, 40/40 inside both hidden limits,
  10/10 impossible pairs no deal; intent routing 120/120; 50 concurrent conversations 50/50; Vertex AI evaluation
  autorater found 0 paraphrased leaks across 129 replies; ≈ $1.17 for 1,402 Gemini calls.
- **Live today (production):** signed agent card verified by an outside client with the published key; A2A
  streaming ("working" 0.4 s, answer 4.8 s); Model Armor flagged two injection attempts from an outside agent and one
  from the app; replay protection (second use of a single-use token → 401); pickup pass (buyer can't collect, seller
  collects once, second attempt 409); Google Pay TEST payment with AP2 v0.2 checkout and mandates verified in the
  browser; stock tracked ("12 available" answered from the ledger); goals backfilled and shown; a real-Gemini plan for
  a party goal (two provider steps, each searched, ₹3,000 budget); scheduler jobs running every minute / 15 minutes;
  deep links to every screen; installed-app manifest, icons, service worker and cache.
- **Not tested (needs your devices):** Gemini Nano on a Chrome desktop with the model downloaded; push on the
  installed iPhone app after today's changes; a real outside agent's push webhook.

## 4. What was built and fixed in this review

- **Caps removed** on price checks and Maps lookups (policy `0 = no cap`); UI shows no "N of 5" text.
- **Key-id regression fixed (serious):** the Cloud Run image's Node changed JWK property order between deploys, which
  changed the derived key id and made every earlier receipt, cart, mandate and pickup pass fail verification. Same
  key, same signatures — only the label moved. Key ids are now RFC 7638 thumbprints (runtime-independent), older
  labels are published as aliases, retired keys (`RECEIPT_KEYS_PREVIOUS`) keep verifying their records, and every
  verifier tries every published key. Tests #102–104.
- **Deep links:** `?screen=context|people|sharing|activity|settings` opened the chat; now any screen opens (the
  installed app's shortcuts rely on this).
- **Sharing screen** said "Sharing is on" and "Paused: …" at once; wording now matches the state.
- **Installed app shortcuts:** Requests, "Scan a shop's QR", "My context".
- Test-attack goal removed from @ahtishay; three cap tests now set a cap explicitly.

## 5. UI review

Judged against the vision's home experience ("what I need, what I offer, what my agent is doing, what needs me")
and the earlier UX research (summary first, progressive disclosure, 1–3 actions, visible progress).

| Screen | Verdict | Notes |
|---|---|---|
| First screen (Google or guest) | Good | Clear promise, one primary action, QR context line ("You're opening @shop's agent"). |
| Chat | Good | Request/offer cards, live conversation cards with the 5-step bar, summary first, details folded. Weak spot: a declined job-search card reads "Ended the conversation. / 'Yes'" — the key answer shown is the wrong one (see §8). |
| Requests | Good, now the hub | Goals with state, next step, budget, plan steps and settings; then conversations. On a phone the "NEEDS YOU" tag wraps under long titles — acceptable. |
| Context | Good | Tiers, add-fact, stock/slots/connector controls on offerings. "Connect a POS" shows a signing key once — fine for shops with a tech partner, too technical for a kirana owner (roadmap: partner integrations). |
| People | Good | QR card with Download/Copy/Scan, agent address, add by handle. |
| Sharing | Good (wording fixed) | Rule builder is compact; "How much" / "Check with me first" are plain words. |
| Activity | Good | Honest empty state. |
| Settings | Good | On-device AI (download, three processing modes), app & notifications, account. Dense but every row explains itself. |
| Pickup pass, Verify | Good | Plain words, test-mode disclaimer, verification result in one line per item. |
| Sidebar / phone | Good | Needs-you button first, install + notifications prompts, nav, agent address, guest reminder. |

Consistent dark theme, mono labels and hairlines throughout; 16 px gutters on phones; no horizontal scroll at 375 px.
Not done: accessibility audit (keyboard paths, screen-reader labels on icon buttons), Hindi UI, user testing with
shopkeepers. These are the UX items I would do first after submission.

## 6. Installed app (PWA)

Verified on the live site: manifest (`standalone`, scope `/`, theme colour, 192/512/SVG icons all 200), service
worker active with the full shell cached (`collab-shell-v4`), network-first with a 3-second fallback to the device
copy, version check on resume (reloads into a new build unless typing), Firestore offline cache for conversations and
inbox, private-notes cache for offline answers with Gemini Nano, push via Firebase Cloud Messaging (verified on your
iPhone and Mac earlier). Shortcuts now: Requests, Scan a shop's QR, My context. Google Pay in the installed app opens
the sheet in a new window — acceptable; iPhone notifications work only in the installed app (documented in Settings).

## 7. How Collab compares

| Who | What they do | How Collab differs |
|---|---|---|
| Google AI Mode + UCP (with Shopify, Jan 2026) | Agentic checkout at approved US merchants from Google's own surfaces | One-sided: the buyer's assistant buys from a catalogue at list price. Collab represents **both** sides, negotiates inside private limits, and works for a kirana with no catalogue. |
| OpenAI/Stripe ACP (Instant Checkout, reported sunset Mar 2026) · Perplexity Instant Buy | Buy inside the chat from large merchants | Discovery + checkout for online retail; no negotiation, no local pickup, no services. |
| Amazon "Alexa for Shopping" / Buy for Me | Price-watch and auto-buy inside Amazon's ecosystem | Closed ecosystem; Collab is an open A2A agent per person, any provider can join. |
| CarEdge negotiation agent | Haggles with car dealers for a fee | One category, one side. Collab is general, bilateral, and the limits stay private on both sides. |
| Haggle (open source), AgenticPay (research) | Buyer/seller agents negotiate | Prototypes without payment, pickup, stock, trust or verification. |
| ONDC / Beckn (India) | Open network for buyer and seller apps | Complementary: Collab's agents could become a Beckn buyer/seller app; ONDC has no per-person agent today. |

What is new in combination: per-person agents with a published, signed identity; selective disclosure enforced by
code before the model; negotiation with private limits on both sides; physical handover with a one-time pass; a
record a third party can verify offline; and goals that span several providers under one budget.

## 8. Known gaps and risks (honest)

1. **Organisations and staff roles** (TP-01) are not built: a shop is one account.
2. **Payments are simulated.** Google Pay TEST only; "paid another way" covers cash/UPI by hand. Real UPI needs a
   provider and a settlement webhook (one connector away, by design).
3. **Chat card shows the wrong key answer** on a declined conversation (the last answered question, not the decisive
   one) — cosmetic, see §5.
4. **Semantic leak detection** relies on the Vertex autorater in the benchmark; production Model Armor screens
   injection and sensitive data, not paraphrase.
5. **On-device Gemini Nano** is desktop Chrome only; phones use cloud Gemini (clearly shown in Settings).
6. **No accessibility audit, no Hindi UI, no user testing** with real shops.
7. **Scale:** benchmarked at 50 concurrent conversations on one process; Cloud Run max 2 instances.
8. **Repository not pushed** (43 commits local); demo video not recorded.
